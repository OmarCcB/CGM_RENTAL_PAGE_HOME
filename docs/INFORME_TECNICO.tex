\section{Resumen Ejecutivo}
% ============================================================================

El sitio web de \textbf{CGM Rental} es una aplicacion web monolitica desarrollada
en Python con el framework \textbf{Flask}, que sirve como vitrina corporativa y
catalogo de productos de la empresa para sus operaciones en \textbf{Peru} y
\textbf{Argentina}.

\subsection{Objetivos del producto}
\begin{itemize}[leftmargin=*]
    \item Presentar la oferta de \textbf{alquiler y venta de maquinaria pesada}
        de CGM Rental en sus dos paises de operacion.
    \item Permitir al usuario navegar el catalogo por sector (Construccion,
        Mineria, Agricola, Energia) y por tipo de equipo.
    \item Generar \textbf{leads comerciales} mediante un cotizador con carrito
        de equipos y formulario de contacto.
    \item Centralizar canales corporativos: \textbf{blog/novedades}, \textbf{portal
        de proveedores}, \textbf{canal de denuncias}, \textbf{certificaciones ISO},
        seccion \textbf{Capacita} y \textbf{Leasing Operativo}.
    \item Adaptar la experiencia a cada pais (banderas, telefonos, redes,
        sucursales, productos disponibles) de manera transparente.
\end{itemize}

\section{Modelo de Datos}
% ============================================================================

La base de datos es un fichero SQLite (\texttt{cgm.db}) ubicado en la raiz del
proyecto. El esquema se crea de forma idempotente al arrancar la aplicacion
mediante la funcion \texttt{init\_db()} de \texttt{database.py}, y se completa
con datos iniciales mediante \texttt{seed\_db()} en \texttt{app.py}.

\begin{infobox}
\textbf{Importante.} Las migraciones de columnas se hacen con
\texttt{ALTER TABLE} envuelto en \texttt{try/except}: si la columna ya existe
se ignora silenciosamente. No existe un sistema formal de migraciones tipo
Alembic.
\end{infobox}

El sitio sirve dos vitrinas separadas bajo el mismo dominio:

\subsection{Deteccion automatica de pais}

La ruta raiz \texttt{/} ejecuta \texttt{\_detect\_country\_from\_ip()} que lee
el header \texttt{CF-IPCountry} de Cloudflare:

\begin{lstlisting}[language=Python]
def _detect_country_from_ip(_ip=None):
    cf = request.headers.get("CF-IPCountry", "").strip().upper()
    # XX = Cloudflare no detecto pais  |  T1 = Tor
    if cf and cf not in ("XX", "T1"):
        return {"PE": "pe", "AR": "ar"}.get(cf)
    return None
\end{lstlisting}

Si Cloudflare reporta PE o AR, redirige a la vitrina correspondiente. Cualquier
otro pais (o IPs locales) cae a \texttt{DEFAULT\_COUNTRY = "pe"}. Ver detalles
de configuracion del servidor en \texttt{GEOIP\_SETUP.md}.

\subsection{Filtrado de productos por pais}

El campo \texttt{show\_arg} en la tabla \texttt{products} controla qu\'e
productos aparecen en cada vitrina:

\begin{itemize}[leftmargin=*]
    \item Si el usuario est\'a en \texttt{/pe/}: se muestran productos con
        \texttt{show\_arg = 0 OR show\_arg IS NULL}.
    \item Si el usuario est\'a en \texttt{/ar/}: se muestran productos con
        \texttt{show\_arg = 1 OR show\_arg IS NULL}.
\end{itemize}

\subsection{Unidades multivalor}

El campo \texttt{unidad} acepta varios sectores separados por pipe
(\texttt{Construccion|Mediana Mineria}). Para que las consultas SQL hagan
match correctamente, existe el helper \texttt{\_unidad\_clause()} en
\texttt{app.py}:

\begin{lstlisting}[language=Python]
def _unidad_clause(unidad, col="unidad"):
    return (
        f"({col} = ? OR {col} LIKE ? OR {col} LIKE ? OR {col} LIKE ?)",
        [unidad, f"{unidad}|%", f"%|{unidad}|%", f"%|{unidad}"]
    )
\end{lstlisting}

\texttt{/api/cart}        & GET / DELETE  & Lee el carrito completo o elimina un item / vacia el carrito. \\
\texttt{/api/denuncia}    & POST          & Persiste denuncia (tipo + descripcion) y envia email confidencial. \\
\texttt{/api/proveedor}   & POST          & Registra proveedor y envia email a CGM. \\
\bottomrule
\end{longtable}

Definido en \texttt{base.html}. Es un panel + boton que se muestra en todas las

acumulados sin abandonar la navegacion. La UI se mantiene sincronizada con la

% ============================================================================
\section{Productos Relacionados con Prioridades}
% ============================================================================

En la ficha de cada producto (\texttt{/producto/<slug>/}) se muestran hasta
6 productos relacionados. El algoritmo aplica dos niveles de prioridad y
combina ambos resultados:

\begin{enumerate}[leftmargin=*]
    \item \textbf{Nivel 1.} Mismo \texttt{tipo} + misma \texttt{unidad} + mismo
        \texttt{tag} (excluyendo el producto actual). Maximo 3.
    \item \textbf{Nivel 2.} Mismo \texttt{tag} + misma \texttt{unidad}, pero
        \texttt{tipo} distinto. Completa los espacios restantes hasta llegar a
        6.
\end{enumerate}

Ambos niveles aplican el filtro \texttt{show\_arg} segun el pais y usan
\texttt{ORDER BY RANDOM()} para que la rotacion sea natural.

\section{Emails Transaccionales}
\label{sec:email}
% ============================================================================

La funcion \texttt{send\_email()} en \texttt{app.py} envia correos HTML via
SMTP plano (TLS en puerto 587). Todas las credenciales viven en variables de
entorno:

\begin{lstlisting}[language=bash]
SMTP_HOST=smtp.gmail.com
SMTP_PORT=587
SMTP_USER=...@cgmrental.com
SMTP_PASS=<app-password>
EMAIL_DESTINO=contacto@cgmrental.com
\end{lstlisting}

Las plantillas HTML estan \textbf{embebidas en el codigo Python}, no en
archivos separados. Cada formulario tiene su plantilla:

\begin{itemize}[leftmargin=*]
    \item Cotizacion: en \texttt{/api/contacto}.
    \item Denuncia: en \texttt{/api/denuncia} (estilo corporativo verde / lima).
    \item Proveedor: en \texttt{/api/proveedor}.
\end{itemize}

\begin{warningbox}
Si \texttt{SMTP\_USER} o \texttt{SMTP\_PASS} no estan configurados,
\texttt{send\_email()} devuelve \texttt{False} silenciosamente. La cotizacion
si se guarda en la base de datos, pero no llega al correo de ventas. Verifica
el \texttt{.env} en cada despliegue.
\end{warningbox}

\subsection{Context processor}

\texttt{app.py} inyecta variables globales en todas las plantillas:

\begin{lstlisting}[language=Python]
@app.context_processor
def inject_globals():
    path_parts = request.path.strip('/').split('/')
    cc = path_parts[0] if path_parts and path_parts[0] in COUNTRIES else 'pe'
    return {
        "cart_count": cart_count(cc),
        "COUNTRIES":  COUNTRIES,
        "PARTNERS":   PARTNERS,
    }
\end{lstlisting}

Asi cualquier template puede usar \texttt{\{\{ cart\_count \}\}},
\texttt{\{\{ COUNTRIES \}\}} o \texttt{\{\{ PARTNERS \}\}} sin pasarlas
explicitamente.

\section{Consideraciones de Seguridad}
% ============================================================================

\begin{itemize}[leftmargin=*]
    \item \textbf{SQL Injection:} todas las queries usan parametros
        \texttt{?}. Las concatenaciones con f-strings se hacen solo con
        valores de una whitelist (\texttt{arg\_filter}, \texttt{\_unidad\_clause}).
    \item \textbf{CSRF:} actualmente \textbf{no hay token CSRF} en los
        formularios. Si el sitio creciera para manejar autenticacion de
        usuarios finales, conviene incorporar Flask-WTF.
    \item \textbf{XSS:} Jinja2 escapa por defecto. El campo
        \texttt{blog\_posts.contenido} \textbf{si} se renderiza con
        \texttt{|safe} porque contiene HTML --- el contenido debe venir de
        fuentes confiables (admin).
    \item \textbf{Cookie de sesion:} firmada con \texttt{FLASK\_SECRET\_KEY};
        si esta variable no se setea en produccion el sitio funciona pero las
        sesiones son falsificables.
    \item \textbf{Subida de archivos:} solo se permite via panel admin (que
        valida extensiones y tamano $\leq$ 10 MB).
\end{itemize}

\section{Hoja de Ruta Sugerida}
% ============================================================================

\subsection{Mejoras tecnicas recomendadas}
\begin{enumerate}[leftmargin=*]
    \item Anadir un sistema formal de migraciones (Alembic) en lugar de los
        \texttt{ALTER TABLE} con \texttt{try/except}.
    \item Implementar tokens CSRF en los formularios publicos.
    \item Migrar \texttt{products.json} a fuente unica (la base de datos) y
        desactivar el seed automatico en produccion.
    \item Anadir tests automatizados (\texttt{pytest} + \texttt{Flask-Testing}).
    \item Habilitar logging estructurado en archivos rotativos.
    \item Considerar mover el envio de email a una cola asincronica
        (\texttt{Celery} + \texttt{Redis}) para no bloquear el request.
\end{enumerate}

\subsection{Limpieza de archivos sugerida}
\begin{itemize}[leftmargin=*]
    \item Eliminar \texttt{cgm\_rental.db} (0 bytes).
    \item Eliminar \texttt{temp\_compare.json} y \texttt{temp\_gen\_excel.py}.
    \item Consolidar los scripts utilitarios (\texttt{apply\_db\_fixes.py},
        \texttt{dup\_arg.py}, \texttt{fix\_routing.py}, \texttt{gen\_*.py})
        en una carpeta \texttt{scripts/}.
\end{itemize}

\section{Glosario}

\begin{description}[leftmargin=*]
    \item[\texttt{slug}] Identificador URL-friendly de un producto o post.
        Ejemplo: \texttt{excavadora-john-deere-210g}.
    \item[\texttt{tag}] Categoria comercial: \texttt{alquiler} o \texttt{venta}

        aparecer en la vitrina de Argentina.
    \item[\texttt{ficha\_url}] Ruta a la ficha tecnica en PDF, almacenada en
        \texttt{static/docs/fichas/}.
\end{description}
